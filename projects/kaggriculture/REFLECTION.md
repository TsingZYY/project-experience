# 最终复盘

## 完成了什么

项目交付了观察驱动的独立游戏 Agent，以及能够比较候选与控制的本地评估记录。最终门控只在可定义的需求场景扩张，并以未触发行为的一致性约束改动范围；独立文件又经过历史动作比对和路径加载检查。

## 最有价值的认识

**高均值不应掩盖尾部失败。** 早期扩张策略即使赢过弱对手，也可能比自己的基线差很多。对手胜率和相对控制收益必须分别看。

**实验条件需要检查。** 同 seed 不自动代表同一外部环境，交换座位也不代表农场条件完全对齐。引擎随机数耦合和物理座位差异实际改变了验证口径。

**未改变的场景也需要证据。** 1,147 个未触发座位与控制精确一致，说明候选分支没有在其他场景悄悄改变行为；这是可维护策略的重要部分。

**打包正确性应与策略效果分开。** 7,190 动作的一致性解决本地模块内联后的身份问题，不能替代更多对手、更广分布或线上验证。

## 没有完成或不能证明的事

- 尚无已核实的官方提交、排名或对顶级 Agent 的表现。
- 仅 53 个触发座位，并不覆盖所有罕见需求与供应状态。
- 分析器经过运行后修订，不能将该结果包装为全程未修改的确认实验。
- 原引擎下的同 seed 配对没有完全隔离需求路径；已有增量不等于纯粹的产能因果效应。
- 此策略是规则与调度决策，没有训练强化学习模型。

## 如果继续

在新一轮数据出现前冻结分析器和失败门槛，增加强对手及尾部场景，并把 SDK 与线上运行差异单独核实。若改变生产结构，应同时看本方现金、对手现金、库存路径和最终 margin，避免把对手损失误当成本方经营能力。

本轮保留完整历史候选和判断依据，没有生成新的对局或线上成绩。
