## 项目问题

在有共享市场、生产周期和劳动力约束的经营游戏中，增加产能不一定增加最终收益。项目围绕牛奶生产与需求观察设计决策策略，并建立对照流程，检查候选是否只在目标场景改变行为。

最终保存的策略默认运行 8 牛控制策略；只在第 9 天已经观察到至少 3 个奶类商店时扩张到 9 牛，之后保留扩张状态。未触发时回到控制策略。

## 已保存的本地记录

- 100 个预留种子、6 类对手、候选／控制两策略及双座位，共 2,400 场。
- 53 个实际触发座位相对匹配基线的 margin 全部增加；1,147 个未触发座位与控制行为精确一致。
- 打包 QA 中，10 局共 7,190 个动作与参考候选一致；2 个官方 SDK 按文件路径加载案例通过。

这里的 margin 是一场游戏中本方终局分数减去对手分数。候选和控制在各对手的 seed 级记录中都为 100/100 获胜，不能据此声称胜率提高。

## 当前证据边界

这是本地控制对手上的候选与完整源码快照，没有已核实的 Kaggle 排行榜成绩。历史打包状态为 `built-and-tested-not-submitted`，与作品集本身的 GitHub 发布状态不同。本次只整理资料、复制源码并核对身份，没有重新运行对局。

原分析器在发现座位触发差异后有留痕修订；候选和原评估数据未变。官方引擎的随机数调用也使相同 seed 不保证相同后续需求路径，详情见 [研究笔记](NOTES.md)。
