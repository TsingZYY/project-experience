## 1. 从关系到查询单位

教务模式中，学生、人员、课程开设、科目、学期及学程是不同实体。编写查询前，需要确定输出按人、课程开设、科目还是学程分组。

例如当前Q1代码把科目与某年份曾开设的条件通过EXISTS联系起来，同时对学生通过的科目去重统计。年份限制作用于科目的开设条件，不直接等同于学生必须在同一年修读。这种区别会改变连接与筛选位置。

## 2. 多表连接、去重和聚合

视图使用JOIN、WHERE、GROUP BY、HAVING和相关子查询表达跨表规则。COUNT(DISTINCT ...)与COUNT(*)回答不同问题：连接后的多行不一定代表不同对象。

Q2分别按年份计算合格成绩的平均值，再关联两组统计量比较差异，并对参与均值计算的记录设置数量要求。这样将两个年份的样本定义分别固定，避免在混合行上直接计算含义不明的差值。

## 3. 从集合查询到过程规则

| 函数 | 代码中的处理方向 |
|---|---|
| Q7 | 根据学程代码与开始年份识别队列，计算队列人数及后续保留统计，处理无效学程或队列。 |
| Q8 | 查找学生及目标学期，比较当前与之前学期的成绩／通过情况，返回学业状态。 |
| Q9 | 查找学生与方向信息，计算整体及专业相关WAM摘要和差值文本。 |
| Q10 | 按学期遍历记录，返回课程行、学期汇总及累计成绩摘要。 |

这些描述来自实际函数体，不代表其对全部隐藏检查均正确。具体字段、有效成绩和学分口径以代码及依法取得的原课程定义为准。

## 4. 边界处理需要明确

- 外部学号与内部学生ID分开查找，不能假定二者相同。
- 无法识别学生、学程或队列时返回明确文本。
- 某学期没有有效选课记录时，不使用一个凭空计算的成绩。
- NULL、未通过、无成绩和缺失记录应按原规则区分。
- 数值计算与最终TO_CHAR格式化分开，避免把展示字符串当作后续数值输入。

## 5. 为什么本包不带测试数据

学校提供的schema、数据库、check.sql及题面不是本人编写部分。它们未被复制到作品集，避免把个人SQL实现和教学材料混在一起。

原目录的运行脚本还包含本地数据库凭据，不适合原样公开。本包没有这些脚本，也没有自行补写测试数据或参考答案。
